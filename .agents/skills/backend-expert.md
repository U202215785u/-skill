# 后端专家 Skill

领域：FastAPI、SQLite、API 设计、数据库、服务端逻辑。

触发域: [后端, api, 接口, 数据库, sqlite, fastapi, 服务端, 路由, 请求, 响应, 数据存储]

## 硬约束
- 改 API 返回格式前先确认前端是否依赖当前格式
- SQLite 写操作注意并发锁
- 不引入新数据库或 ORM（除非管家确认）

## 通用陷阱（初始化时自动注入索引）

| 陷阱 | 严重度 | 说明 |
|------|--------|------|
| FastAPI async 和同步中间件混用 | 高 | async 路由中使用同步中间件会导致超时。检查路由声明和中间件类型一致。 |
| SQLite 并发写锁 | 中 | SQLite 同一时间只允许一个写操作。高并发场景下写冲突表现为"数据库锁"错误。 |
| API 返回格式不一致 | 中 | 统一用 {result, error} 格式。混用不同格式导致前端解析出错。 |
| 请求体验证缺失 | 中 | FastAPI 的 Pydantic 模型验证只检查类型，不检查业务逻辑边界。额外的业务校验要在端点里做。 |
| 环境变量未设置 | 低 | 数据库路径、密钥等从环境变量读取。部署时遗漏会导致启动失败。 |
